# Threat Model

## 1. Threat Actors & Attack Surfaces

| Threat ID | Attack Vector | Mitigation in `gke-model-admission-controller` | Verification Test Case |
|---|---|---|---|
| **TM-01** | **Unannotated Shadow Model Deployment**: An operator deploys an LLM serving Pod in `ai-serving` without referencing a `ModelArtifact` to bypass provenance checks. | Default-deny in enforced namespaces (`trust.gke.dev/enforce: "true"`): any workload lacking `trust.gke.dev/model-artifact` is rejected. | `N-01` (`MissingModelArtifactReference`) |
| **TM-02** | **Mutable Tag Swap (TOCTOU)**: An attacker overwrites `:latest` or `:v1` in the registry after qualification. | Both `ModelArtifact.spec.artifact.uri` and container `image` fields require `@sha256:<64-hex>` immutable digests. | `N-03` (`InvalidArtifactURI`), `N-24` (`MutableRuntimeImage`) |
| **TM-03** | **Untrusted External Registry Pull**: A workload references a model bundle hosted in an unapproved external registry. | `ClusterModelTrustPolicy.spec.allowedRegistries` prefix enforcement before any network call. | `N-04` (`UntrustedRegistry`) |
| **TM-04** | **Silent Model Weight / Tokenizer / Config Tampering**: A model weight shard (`model.safetensors`), `config.json`, or `tokenizer.json` layer is modified in the registry. | OCI layer descriptor digests are compared against `bundle-manifest.json`, OMS resource digests, and CycloneDX component hashes; `bundle_id` is recomputed via JCS. | `N-10`, `N-11`, `N-12` (`InvalidBundleManifest`) |
| **TM-05** | **Trojan File Injection in OCI Bundle**: An extra undeclared layer is appended to the OCI manifest. | Rejected when `allowUnknownBundleFiles: false`. | `N-13` (`InvalidBundleManifest`) |
| **TM-06** | **Cross-Domain Key Confusion**: A compromised CI evaluation runner uses its valid `evaluator` private key to forge an OMS model signature or Release Qualification attestation. | Strict trust-domain isolation (`modelSigners` vs `evaluators` vs `releaseAuthorities`) with `AllDomainCandidates` cross-domain detection. | `N-14`, `N-15`, `N-16`, `N-17` (`UntrustedModelSigner`, `UntrustedEvaluator`, `UntrustedReleaseAuthority`) |
| **TM-07** | **Post-Hoc Evaluation Forgery**: An operator binds an old or synthetic `report.json` after the fact using `evidence bind-eval` (`POST_HOC_OPERATOR`). | Policy enforces `requireNativeEvaluatorBinding: true` and `rejectPostHocBinding: true`, accepting only `NATIVE_EVALUATOR` attestations. | `N-18` (`PostHocEvaluationRejected`) |
| **TM-08** | **Evidence Mix-and-Match / Replay Attack**: Attacker attaches a passing evaluation from Model A (or an old evaluation run, or a different test suite) to Model B. | Verifies `subject[0].digest == bundle_id`, `suite.digest == expectedSuiteDigest`, `dataset.digest == expectedDatasetDigest`, timestamp `< maxEvidenceAgeHours`, and 5-point digest equality in `release-qualification/v1`. | `N-19`, `N-20`, `N-21`, `N-22`, `N-23` |
| **TM-09** | **Runtime Image or Serving Config Drift**: Qualified model is deployed with an unapproved serving container image or altered prompt/safety template (`serving_config_digest`). | Webhook compares Pod container images and `trust.gke.dev/serving-config-digest` against the attested values in `ModelArtifact.status`. | `N-25` (`RuntimeImageMismatch`), `N-26` (`ServingConfigDigestMismatch`) |
| **TM-10** | **LoRA Adapter Base-Model Substitution**: A LoRA adapter qualified on Base Model X is loaded onto Base Model Y at runtime. | Controller and webhook verify `verified_base_bundle_id` against the referenced base `ModelArtifact`'s `status.verifiedBundleID`. | `N-27` (`LoRABaseModelUnverified`) |
| **TM-11** | **Stale Verification / Policy Downgrade**: Trust policy keys or exemptions are rotated, or `verificationTTLSeconds` expires, while an old `ModelArtifact` remains cached. | Webhook synchronously recomputes `policyDigest` and checks `status.policyDigest == activePol.PolicyDigest` and `now < status.validUntil`. | `N-28` (`VerificationExpired` / `PolicyDigestMismatch`) |
| **TM-12** | **Denial-of-Service via Huge Blob Download**: A malicious `ModelArtifact` points `config` or a referrer layer to a multi-GB weight blob to OOM the controller. | `Client.FetchMetadataBlob` refuses weight media types/roles and caps all reads at `MaxMetadataBlobBytes` (`16 MiB`) with `io.LimitReader`. | Verified in `internal/registry/client.go` |
