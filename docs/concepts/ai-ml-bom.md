# Concept: CycloneDX 1.7 AI/ML-BOM (`application/vnd.cyclonedx+json`)

Every model admitted by `gke-model-admission-controller` (when `requireCycloneDXBOM: true`) must carry a verified **CycloneDX 1.7 AI/ML Bill of Materials (AI/ML-BOM)** attached as an OCI v1.1 Referrer (`artifactType: application/vnd.cyclonedx+json`).

---

## 1. What the AI/ML-BOM Captures

Generated by `ai-model-provenance bom generate`, the CycloneDX 1.7 JSON document includes:

1. **Root `machine-learning-model` Component (`metadata.component`)**:
   - Bound to `bundle_id` via `hashes: [{alg: "SHA-256", content: "<64-hex>"}]` and `ai-model-provenance:bundle_id` properties.
   - Records model architecture, primary format (`safetensors`), and LoRA relationship metadata (`lora_verification_status`, `verified_base_bundle_id`).
2. **Per-File Sub-Components (`components[]`)**:
   - Every file in the model bundle (`config.json`, `model.safetensors`, `tokenizer.json`, etc.) is listed with its exact `SHA-256` hash, byte size, and role property (`org.devenes.model.file.role`).

---

## 2. How Stage 5 Verifies the AI/ML-BOM

In Stage 5 of [`internal/verification/verifier.go`](../../internal/verification/verifier.go):

1. Discovers the referrer with `artifactType: application/vnd.cyclonedx+json` via `/v2/<repo>/referrers/<digest>`.
2. Calls `verify.VerifyBOMBytes(rawBOM, &bm, descriptors)` in memory:
   - Validates CycloneDX `1.7` (or `1.6`) specification compliance.
   - Verifies that the root component hash equals `bm.BundleID`.
   - Verifies 1:1 correspondence between `components[]` file hashes and the observed OCI layer descriptors (no missing files, no extra files, no hash mismatches).
   - When the model is a LoRA adapter, verifies that the BOM records the matching `verified_base_bundle_id`.
   - Computes the canonical RFC 8785 JCS digest (`bomRes.CanonicalHash`), which is subsequently checked against `release-qualification/v1` in Stage 7 (`N-23`).
